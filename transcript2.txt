  ---
  初回アクセス時（例: /users を直接開く）

  ブラウザ → GET /users → Hono
                             ↓
                      c.render('Users/Index', { users: [...] })
                             ↓
                 @hono/inertia ミドルウェアが
                 X-Inertia ヘッダーを確認 → なし
                             ↓
                 フル HTML を返す（Reactアプリ全体 + データ）
                             ↓
            <div id="app"
  data-page='{"component":"Users/Index","props":{...}}'/>
                             ↓
                 Reactがマウントし、Users/Index.tsx を描画

  ---
  2回目以降（<Link> をクリック）

  Link href="/users/new" をクリック
          ↓
  Inertia が fetch をインターセプト
  X-Inertia: true ヘッダー付きで GET /users/new
          ↓
  Hono → c.render('Users/New', { values, errors })
          ↓
  @hono/inertia: X-Inertia ヘッダーを検出 → フルHTMLではなくJSONを返す
    { "component": "Users/New", "props": { "values": {...}, "errors": {} } }
          ↓
  Inertia クライアントが Users/New.tsx を動的ロードして差し替え
  （ページリロードなし）

❯ hono分からんけど、 cloudflare                                                 
  workers使ったら、hono部分はバックエンドに隠蔽されるの？                       

● 良い疑問です。関係を整理します。

  ---
  Cloudflare Workers と Hono の関係

  ┌─────────────────────────────────┐
  │       Cloudflare Workers        │  ← 実行環境（Node.js の代わり）
  │                                 │
  │  ┌───────────────────────────┐  │
  │  │         Hono              │  │  ← フレームワーク（Express の代わり）
  │  │  .get('/users', ...)      │  │
  │  │  .post('/users', ...)     │  │
  │  └───────────────────────────┘  │
  └─────────────────────────────────┘

  隠蔽されるわけではなく、Hono が Workers 上で動く。 関係性は「Node.js 上の
  Express」と同じです。

  ---
  ビルド後の実態

  pnpm build すると:

  dist/
    hono_inertia_example/
      index.js        ← Hono
  のコードが全部入ったWorker（これがCFにデプロイされる）
    client/
      assets/         ← React の JS/CSS（静的ファイルとして配信）

  ブラウザから見えるのは HTTP のレスポンスだけで、Hono
  のコードは見えません。でも「Cloudflare が Hono
  を隠してくれる」のではなく、あなたが書いた Hono のルートがそのまま Workers 
  として動くという感じです。

  ★ Insight ─────────────────────────────────────
  - Cloudflare Workers は V8 エンジン（Chrome
  と同じ）ベースのサーバーレス環境。Node.js とは別物で、fs や net などの Node
  API は使えないが、Hono はそれを意識して設計されており Workers ネイティブに動く
  - 従来の「サーバー常駐型」と違い、Workers
  はリクエストごとに起動する。だからこの data.ts
  のインメモリ配列はリクエストをまたいで永続しない（デプロイ環境では DB
  が必要になる理由がここにある）
  ─────────────────────────────────────────────────

  ---
  つまり「Hono を書く = Workers のバックエンドを書く」です。フロントから見れば隠
  れていますが、あなたが明示的に書く必要があります。
